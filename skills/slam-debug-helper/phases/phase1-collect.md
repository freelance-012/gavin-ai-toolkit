# Phase 1: 信息收集

## 目标

收集与故障相关的所有信息：项目规格、评估结果、日志、参数配置，为根因诊断提供依据。

## 触发词

- "收集信息"
- "收集诊断数据"

## 依赖

Phase 0 的故障分类结果

## 输入参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| project_path | string | ✅ | 项目根目录绝对路径 |
| fault_type | string | ✅ | Phase 0 确定的故障类型 |

## 输出产物

不生成文件，但收集的信息供 Phase 2 使用。

## 执行步骤

### Step 1: 读取项目规格

读取 `{project}/.specs/project-spec.md`，提取以下信息：

**所有故障类型都需要**：
- 数据集格式和路径
- 真值文件格式
- 系统输出格式
- 日志格式和目录

**根据故障类型，额外关注**：

| 故障类型 | 重点读取 |
|---------|---------|
| 轨迹漂移 | IMU 参数、外参、评估配置 |
| 轨迹发散 | 外参、噪声参数、初始化配置 |
| 跟踪丢失 | 特征提取参数、相机参数 |
| 初始化失败 | 初始化配置、运动要求 |
| 回环检测失败 | 回环检测参数、描述子阈值 |

### Step 2: 读取评估结果（如果有）

检查是否存在 eval-runner 的评估结果：

```bash
# 查找最新的评估结果
ls -td {project}/.specs/eval-results/*/eval-report.md 2>/dev/null | head -1
```

如果存在，读取：
- 评估指标（ATE RMSE、RPE 等）
- 误差时序分析
- 异常区间列表

**特别关注**：
- 误差随时间的变化趋势
- 误差突增的时间戳区间
- 最大误差出现的位置

### Step 3: 读取日志（如果有）

根据 spec 中的日志配置，查找并读取相关日志：

```bash
# 查找日志目录
ls -td {project}/.specs/logs/*/session-summary.md 2>/dev/null | head -1
```

**根据故障类型，重点关注**：

| 故障类型 | 日志关注点 |
|---------|-----------|
| 轨迹漂移 | 优化后的位姿变化、IMU 零偏估计、尺度变化 |
| 轨迹发散 | 初始化阶段、外参加载、噪声参数 |
| 跟踪丢失 | 特征数量变化、内点比例、跟踪状态 |
| 初始化失败 | 初始化尝试次数、运动激励检测 |
| 回环检测失败 | 回环候选数量、验证得分、几何验证 |

**提取关键日志片段**：
- 故障发生时间戳前后的日志
- 包含错误/警告的日志
- 关键状态变化的日志

### Step 4: 读取参数配置

读取项目的参数配置文件：

```bash
# 常见配置文件位置
{project}/config/*.yaml
{project}/config/*.json
{project}/params/*.yaml
{project}/settings/*.yaml
```

**根据故障类型，重点关注**：

| 故障类型 | 参数关注点 |
|---------|-----------|
| 轨迹漂移 | IMU 噪声参数、优化参数、外参 |
| 轨迹发散 | 外参（平移单位）、噪声参数、坐标系定义 |
| 跟踪丢失 | 特征提取参数（数量、阈值）、匹配参数 |
| 初始化失败 | 初始化参数（运动阈值、特征阈值） |
| 回环检测失败 | 描述子阈值、几何验证容差、关键帧间隔 |

### Step 5: 检查代码（可选）

如果需要，可以查看关键代码段：

**根据故障类型**：

| 故障类型 | 代码关注点 |
|---------|-----------|
| 轨迹漂移 | IMU 预积分、优化目标函数、边缘化 |
| 轨迹发散 | 外参加载、坐标系转换、初始化逻辑 |
| 跟踪丢失 | 特征提取、特征匹配、跟踪状态机 |
| 初始化失败 | 初始化流程、运动检测、BA 求解 |
| 回环检测失败 | 词袋模型、几何验证、回环融合 |

### Step 6: 汇总收集的信息

```markdown
📋 **诊断信息汇总**

### 项目信息
- 项目名称: {name}
- 框架: {ROS1/ROS2/独立}
- 代码版本: {commit hash}

### 评估结果
- ATE RMSE: {value} {unit}
- 异常区间: {N} 个
- 最严重区间: {start} ~ {end}

### 关键日志
- 故障发生时间: {timestamp}
- 关键事件: {event1}, {event2}

### 参数配置
- IMU 噪声: {gyro_noise}, {accel_noise}
- 外参: {T_cam_imu}
- 特征数量: {max_features}

### 信息完整性
- ✅ 项目规格: 完整
- ✅ 评估结果: 有
- ⚠️ 日志: 部分缺失（{缺失内容}）
- ✅ 参数配置: 完整
```

## 注意事项

1. **信息优先级**：评估结果 > 日志 > 参数配置 > 代码
2. **缺失标注**：如果某些信息缺失，标注"缺失"但不阻塞诊断
3. **时间对齐**：确保日志时间戳与评估结果的时间戳对齐
4. **参数单位**：特别注意参数的单位（mm vs m, rad vs deg）
5. **版本匹配**：确保分析的代码版本与运行版本一致
