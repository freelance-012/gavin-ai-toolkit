# Phase 4: 核心模块深度分析（精读）

## 目标

对 P0 模块逐个进行深度精读。建立公式↔代码映射，产出标准化的精读文档。这是整个七步法中最核心、最有价值的步骤。

## 触发词

- "精读 XX 模块"
- "深入分析 XX"
- "读一下预积分/优化器/初始化"

## 依赖

**必需**:
- `01_拓扑结构分析.md`（模块位置和职责）
- `02_数据流追踪.md`（数据流中的角色和接口）
- `03_模块优先级清单.md`（确认 P0 模块列表）

**可选但强烈推荐**:
- `docs/papers/` 下的主论文及关联论文（用于公式映射）
- `00_资料清单.md`（论文与代码模块的对应关系）

**检查逻辑**：
```
缺失 01/02/03 中任一 → 停止并提示
缺失论文 PDF → 可执行（仅代码分析模式），但会提示"建议补充论文以启用公式映射"
```

## 输入参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| repo_path | string | ✅ | 仓库根目录绝对路径 |
| target_module | string | 条件必填 | 要精读的模块名或路径。如果未指定，则精读所有 P0 模块 |
| paper_path | string | ❌ | 论文 PDF 路径（如果要做公式映射） |

## 输出产物

```
{仓库名}-code-analysis/
└── 04/
    └── {module-name}-deep-dive.md    # 每个精读的模块一份
```

## 执行步骤

### Step 1: 确定精读目标

- 如果用户指定了 `target_module` → 只精读该模块
- 如果未指定 → 从 `03_模块优先级清单.md` 中读取 P0 模块列表，逐个精读

### Step 2: 读取模块源码

**2.1 定位文件**
从 Phase 1/2 的结果中获取该模块的所有源文件（.h/.cpp/.hpp/.cu）。

**2.2 完整读取**
按以下顺序读取：
1. 头文件（.h/.hpp）→ 了解类定义、成员变量、公开接口
2. 实现文件（.cpp）→ 了解具体实现

### Step 3: 分析类结构与数据成员

**3.1 类继承关系**
```
绘制继承图:
  BaseClass (基类)
    └→ DerivedClass (当前类)
         ├→ 成员变量列表 (带类型和含义)
         └→ 方法列表 (公开/保护/私有)
```

**3.2 核心数据成员表**
记录每个重要成员变量的：
- 名称和类型
- 物理含义
- 初始化位置和默认值
- 在哪个函数中被修改

### Step 4: 梳理函数调用链

**4.1 找到入口函数**
通常是以下名称之一：`process`, `update`, `optimize`, `solve`, `run`, `callback`, `handle`

**4.2 追踪调用关系**
```
入口函数 @ 文件:行号
  ├── 内部函数 A @ 文件:行号
  │   ├── 底层运算 X
  │   └── 底层运算 Y
  ├── 内部函数 B @ 文件:行号
  │   └── 底层运算 Z
  └── 返回结果
```

### Step 5: 识别关键数学运算

搜索以下模式的代码：

**5.1 矩阵/向量运算**
```cpp
Eigen::Matrix, Eigen::Vector, .block(), .transpose(),
.inverse(), .norm(), .normalized(), .cross()
```

**5.2 优化求解相关**
```cpp
ceres::Problem, ceres::Solver, ceres::CostFunction,
ceres::AutoDiffCostFunction, ceres::LossFunction,
AddResidualBlock, SetParameterization,
g2o::BaseVertex, g2o::BaseEdge, g2o::OptimizationAlgorithm
```

**5.3 积分/传播相关**
```cpp
integrate, propagate, push_back, midPointIntegration,
rk4, euler, delta_p, delta_v, delta_q, covariance_
```

**5.4 几何投影相关**
```cpp
project, reprojection, pixel2cam, cam2pixel,
undistortPoints, triangulate
```

对每个识别到的数学运算，记录：
- 所在函数和行号
- 输入输出
- 对应的数学概念（如"这行在做旋转向量的指数映射"）

### Step 6: 公式 ↔ 代码映射（如果有论文）

这是本 Phase **最有价值**的部分。

**6.1 读取论文 PDF**
如果提供了 `paper_path` 或在 `docs/papers/` 下找到了对应论文：
- 提取该模块相关的所有公式
- 记录每个公式的编号和所在章节

**6.2 逐一建立映射**

对每个公式：

**(a) 贴出论文原文公式**（LaTeX 格式）

**(b) 写推导说明**
- 用文字解释每项物理含义
- 说明离散化假设
- 标注噪声模型

**(c) 找对应代码**
- 精确到文件名和行号范围
- 逐段注释代码与公式项的对应关系

**(d) 记录差异**
- 论文说 XX，代码做了 YY 近似 → 明确标注
- 原因分析（性能？精度？工程简化？）
- 影响评估（什么场景下会有问题）

**6.3 变量符号映射表**

| 代码变量 | 论文符号 | 含义 | 定义位置 |
|---------|---------|------|---------|

### Step 7: 提取关键参数

扫描该模块涉及的配置参数：
- 从代码中搜索 `param`, `config`, `.yaml` 引用
- 记录参数名、默认值、使用位置
- 推断参数含义（Phase 5 会做更全面的提取，这里只做局部提取）

### Step 8: 生成精读文档

套用 `templates/deep-dive-template.md` 格式（7-section），输出完整的 Markdown 文档。

文档写入 `{仓库名}-code-analysis/04/{module-name}-deep-dive.md`

### Step 9: 循环处理下一个模块

如果还有未处理的 P0 模块，回到 Step 2。

全部完成后，汇报：

```
📋 Phase 4 完成 — 精读报告

已生成 N 份精读文档:
  ✅ 04/imu-preintegration-deep-dive.md      (3,200 字)
  ✅ 04/ba-optimizer-deep-dive.md            (4,100 字)
  ✅ 04/initialization-deep-dive.md          (2,800 字)

覆盖 P0 模块: 3 / 3 (100%)

是否继续 Phase 5 (参数清单)?
```

## 注意事项

1. **质量 > 速度**：宁可一个模块精读透彻，也不要草草扫过所有模块
2. **不确定就标注**：某行代码的作用如果不明确，写"疑似: XXX"，不要编造
3. **公式映射是核心差异化价值**：没有公式的精读只是"代码注释"，有公式对照才是真正的"精读"
4. **注意代码版本差异**：代码可能基于论文的早期版本或有改进，差异是正常的，如实记录即可
5. **大型模块分拆**：如果一个 P0 模块超过 2000 行，考虑按功能子模块分多份报告
