# Phase 1: 交互确认

## 目标

将 Phase 0 的假设逐一向用户展示，获取确认或纠正。同时补充 Phase 0 无法自动获取的信息（如评估指标的业务含义、日志中特定输出的解释等）。

## 触发词

- "确认项目信息"
- "开始交互确认"

## 依赖

Phase 0 的扫描结果（假设清单）

## 输入参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| project_path | string | ✅ | 项目根目录绝对路径 |
| phase0_result | object | ✅ | Phase 0 生成的假设清单 |

## 输出产物

不生成文件，但产出一组**已确认的项目规格信息**，供 Phase 2 生成 spec 使用。

## 执行步骤

### Step 1: 按章节逐项确认

按以下顺序向用户确认每个章节。每次展示一个章节的假设，让用户一次性确认/纠正该章节的所有项。

**顺序**：
1. 项目基本信息
2. 数据集
3. 真值
4. 系统输出
5. 日志
6. 评估
7. 构建配置
8. 运行配置

### Step 2: 每章节的交互格式

对每个章节，按以下格式向用户展示：

```markdown
📋 **{章节名}** — 请确认以下信息

### 已自动识别的信息

| # | 项目 | AI 假设 | 来源 | 置信度 |
|---|------|--------|------|--------|
| 1 | {项目} | {假设值} | {来源文件/代码} | 高/中/低 |
| 2 | ... | ... | ... | ... |

### 需要你补充的信息

| # | 项目 | 说明 |
|---|------|------|
| 1 | {缺失项} | {为什么需要这个信息} |

---
请回复:
- ✅ 确认正确的项（直接跳过或说"确认"）
- ❌ 纠正错误的项（格式: "第N项: 正确值"）
- 📝 补充缺失的项（格式: "补充: 项目=值"）
```

### Step 3: 各章节需要确认的具体内容

#### 3.1 项目基本信息

| 确认项 | 必须 | 说明 |
|--------|------|------|
| 项目名称 | ✅ | 项目的正式名称 |
| 框架 | ✅ | ROS1 / ROS2 / 独立运行 |
| 主要语言 | ✅ | C++ / Python / 混合 |
| 构建系统 | ✅ | CMake / Catkin / Colcon |
| 简述 | ⬜ | 项目做什么（可选，AI 可从 README 提取） |

#### 3.2 数据集

| 确认项 | 必须 | 说明 |
|--------|------|------|
| 数据集名称/来源 | ✅ | 使用的是什么数据 |
| 数据目录 | ✅ | 数据文件在哪里 |
| 图像格式和路径 | ✅ | 图像文件的格式和目录模式 |
| IMU 格式和路径 | ⬜ | 如果有 IMU |
| LiDAR 格式和路径 | ⬜ | 如果有 LiDAR |
| 时间戳单位 | ✅ | 秒 / 毫秒 / 纳秒 |
| 坐标系 | ⬜ | 世界坐标系定义（FLU/ENU/NED） |

#### 3.3 真值

| 确认项 | 必须 | 说明 |
|--------|------|------|
| 真值文件路径 | ✅ | ground truth 文件位置 |
| 格式 | ✅ | TUM / EuRoC / KITTI / 自定义 |
| 列含义 | ✅ | 每列代表什么 |
| 时间戳单位 | ✅ | 与数据集时间戳的关系 |
| 坐标系 | ✅ | 真值的坐标系 |
| 与传感器数据的时间对齐方式 | ⬜ | 最近邻 / 线性插值 / 其他 |

#### 3.4 系统输出

| 确认项 | 必须 | 说明 |
|--------|------|------|
| 轨迹输出路径 | ✅ | 运行后轨迹文件在哪里 |
| 轨迹格式 | ✅ | 与真值相同格式 / 不同格式 |
| 列含义 | ✅ | 每列代表什么 |
| 输出目录约定 | ⬜ | 如何指定输出目录 |
| 其他输出文件 | ⬜ | 地图、关键帧信息等 |

#### 3.5 日志

| 确认项 | 必须 | 说明 |
|--------|------|------|
| 日志框架 | ✅ | ROS / glog / spdlog / cout / 自定义 |
| 日志输出方式 | ✅ | 终端 / 文件 / 两者都有 |
| 日志文件目录 | ⬜ | 如果输出到文件 |
| 日志格式 | ✅ | 每行日志的结构 |
| 主要模块名 | ✅ | 日志中出现的模块标识 |
| 关键日志含义 | ✅ | 高频日志条目的含义（逐条列出） |

**关键日志含义的确认方式**：

AI 从 Phase 0 中提取了 10-20 条高频日志，逐条向用户确认：

```
📋 **日志含义确认**

以下是代码中常见的日志输出，请告诉我每条的含义：

1. `[Frontend] Tracked 120 features, 85 inliers`
   → 你的理解: {等待用户输入}

2. `[Backend] Optimization cost: 0.0234, converged in 3 iterations`
   → 你的理解: {等待用户输入}

3. `[LoopDetector] Candidate: frame 45, score: 0.82`
   → 你的理解: {等待用户输入}

...
```

#### 3.6 评估

| 确认项 | 必须 | 说明 |
|--------|------|------|
| 评估脚本路径 | ✅ | 用什么脚本评估 |
| 运行命令 | ✅ | 怎么调用评估脚本 |
| 输出格式 | ✅ | 评估脚本输出什么 |
| 关注指标 | ✅ | 项目关注的核心指标 |
| 指标含义 | ✅ | 每个指标代表什么、单位 |
| 合格阈值 | ⬜ | 指标达到什么值算合格 |

#### 3.7 构建配置

| 确认项 | 必须 | 说明 |
|--------|------|------|
| 构建系统 | ✅ | CMake / Catkin / Colcon / Make |
| C++ 标准 | ✅ | C++11 / C++14 / C++17 / C++20 |
| 构建目录 | ✅ | 构建产物存放位置 |
| 构建命令 | ✅ | 如何编译项目 |
| 主要依赖 | ✅ | OpenCV, Eigen, PCL 等核心依赖 |
| 编译选项 | ⬜ | 特殊编译选项（如 -march=native, -O3） |
| 构建类型 | ⬜ | Debug / Release / RelWithDebInfo |
| 可执行文件 | ✅ | 编译后的可执行文件路径 |

**构建命令的确认方式**：

AI 从 Phase 0 中提取了构建命令假设，向用户确认：

```
📋 **构建命令确认**

AI 假设的构建命令：
1. 配置命令: `mkdir build && cd build && cmake ..`
2. 编译命令: `make -j4`

是否正确？如果不正确，请提供正确的构建命令。
```

#### 3.8 运行配置

| 确认项 | 必须 | 说明 |
|--------|------|------|
| 可执行文件路径 | ✅ | 运行哪个可执行文件 |
| 运行命令 | ✅ | 如何启动系统 |
| 配置文件 | ✅ | 使用哪个配置文件 |
| 命令行参数 | ✅ | 需要哪些参数（数据集路径等） |
| 环境变量 | ⬜ | 需要设置哪些环境变量 |
| 性能参数 | ⬜ | 线程数、批处理大小等 |
| 运行时依赖 | ⬜ | 需要的数据文件、模型文件等 |

**运行命令的确认方式**：

AI 从 Phase 0 中提取了运行命令假设，向用户确认：

```
📋 **运行命令确认**

AI 假设的运行命令：
./build/slam_system \
  --config config/euroc.yaml \
  --dataset_path /path/to/EuRoC/MH_01 \
  --output_path ./results

是否正确？如果不正确，请提供正确的运行命令。

需要确认的参数：
1. --config: 配置文件路径
2. --dataset_path: 数据集路径
3. --output_path: 输出路径
4. 其他参数...
```

### Step 4: 处理用户回复

对用户每次回复：
- **确认**：标记该项为"已确认"
- **纠正**：更新为正确值，标记为"用户指定"
- **补充**：记录新值，标记为"用户指定"
- **不确定**：标注"待确认"，不阻塞后续流程

### Step 5: 汇总确认结果

所有章节确认后，输出一份汇总：

```markdown
📋 **项目规格确认汇总**

✅ 已确认: {N} 项
📝 用户指定: {N} 项
❓ 待确认: {N} 项（列出不确定的项）

如有遗漏或不确定的项，将标注在最终 spec 中。

是否继续生成 project-spec.md？(Y/n)
```

## 注意事项

1. **减少用户负担**：AI 假设置信度高的项可以直接展示为"我假设是 X，对吗？"，不要让用户从零开始描述
2. **批量确认**：同一章节的项一次性展示，不要一项一项问
3. **允许跳过**：用户可以说"先跳过这个"或"不确定"，不阻塞流程
4. **标注来源**：最终 spec 中区分"AI 自动识别"和"用户指定"的信息
5. **聚焦关键项**：如果某章节所有项置信度都高且用户时间有限，可以快速确认整个章节
