# Phase 2: 根因诊断

## 目标

基于收集的信息，使用故障决策树逐层排查，定位问题的根本原因。

## 触发词

- "诊断根因"
- "分析原因"

## 依赖

Phase 0 的故障分类 + Phase 1 的收集信息

## 输入参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| fault_type | string | ✅ | Phase 0 确定的故障类型 |
| collected_info | object | ✅ | Phase 1 收集的信息 |

## 输出产物

不生成文件，但产生根因分析结果供 Phase 3 使用。

## 执行步骤

### Step 1: 加载故障决策树

根据故障类型，加载对应的决策树：

- `rules/debug-knowledge.md` - 通用决策树
- `rules/frameworks/{framework}-debug-patterns.md` - 框架特化知识（如果有）

### Step 2: 逐层排查

按照决策树，从最可能的原因开始排查。

#### 2.1 轨迹漂移（Drift）决策树

```
轨迹漂移
├─ 1. 检查尺度（单目系统）
│  ├─ 尺度是否收敛？
│  │  ├─ 否 → 根因: 尺度模糊/未约束
│  │  └─ 是 → 继续
│  └─ 尺度变化趋势？
│     ├─ 单调增长 → 根因: 尺度漂移（IMU 零偏/外参）
│     └─ 波动 → 根因: 优化不稳定
│
├─ 2. 检查 IMU 参数
│  ├─ 陀螺仪零偏是否估计？
│  │  ├─ 否 → 根因: 零偏未标定
│  │  └─ 是 → 零偏值是否合理？
│  │     ├─ 否（过大/过小） → 根因: 零偏估计不准
│  │     └─ 是 → 继续
│  └─ 噪声参数是否合理？
│     ├─ 否 → 根因: 噪声参数错误
│     └─ 是 → 继续
│
├─ 3. 检查外参
│  ├─ 外参旋转是否准确？
│  │  ├─ 否 → 根因: 外参旋转错误
│  │  └─ 是 → 继续
│  └─ 外参平移是否准确？
│     ├─ 否 → 根因: 外参平移错误
│     └─ 是 → 继续
│
├─ 4. 检查特征跟踪
│  ├─ 特征数量是否充足？
│  │  ├─ 否 → 根因: 特征不足
│  │  └─ 是 → 内点比例是否合理？
│  │     ├─ 否（<50%） → 根因: 匹配质量差
│  │     └─ 是 → 继续
│  └─ 跟踪是否稳定？
│     ├─ 否 → 根因: 跟踪不稳定
│     └─ 是 → 继续
│
└─ 5. 检查优化
   ├─ 优化是否收敛？
   │  ├─ 否 → 根因: 优化发散
   │  └─ 是 → 继续
   └─ 残差是否合理？
      ├─ 否 → 根因: 残差模型错误
      └─ 是 → 根因: 未知（需要更多日志）
```

#### 2.2 轨迹发散（Divergence）决策树

```
轨迹发散
├─ 1. 检查初始化
│  ├─ 初始化是否成功？
│  │  ├─ 否 → 根因: 初始化失败但系统继续
│  │  └─ 是 → 初始化质量如何？
│  │     ├─ 差（协方差大） → 根因: 初始化不准
│  │     └─ 好 → 继续
│  └─ 初始化后多久发散？
│     ├─ 立即 → 根因: 初始化/外参严重错误
│     └─ 延迟 → 根因: 累积误差/参数问题
│
├─ 2. 检查外参（最高优先级）
│  ├─ 平移单位是否正确？
│  │  ├─ 否（mm vs m） → 根因: 外参平移单位错误
│  │  └─ 是 → 继续
│  ├─ 旋转是否正确？
│  │  ├─ 否 → 根因: 外参旋转错误
│  │  └─ 是 → 继续
│  └─ 坐标系是否一致？
│     ├─ 否 → 根因: 坐标系定义不一致
│     └─ 是 → 继续
│
├─ 3. 检查时间同步
│  ├─ IMU 和相机时间戳是否对齐？
│  │  ├─ 否（偏移>10ms） → 根因: 时间戳偏移过大
│  │  └─ 是 → 继续
│  └─ 时间戳单位是否一致？
│     ├─ 否 → 根因: 时间戳单位不一致
│     └─ 是 → 继续
│
├─ 4. 检查噪声参数
│  ├─ 噪声是否过大（>1.0）？
│  │  ├─ 是 → 根因: 噪声参数过大
│  │  └─ 否 → 噪声是否过小（<1e-6）？
│  │     ├─ 是 → 根因: 噪声参数过小（数值不稳定）
│  │     └─ 否 → 继续
│  └─ 噪声参数单位是否正确？
│     ├─ 否 → 根因: 噪声参数单位错误
│     └─ 是 → 继续
│
└─ 5. 检查数据质量
   ├─ IMU 数据是否正常？
   │  ├─ 否（全零/异常值） → 根因: IMU 数据异常
   │  └─ 是 → 继续
   └─ 图像是否正常？
      ├─ 否（过曝/欠曝/模糊） → 根因: 图像质量问题
      └─ 是 → 根因: 未知（需要更多日志）
```

#### 2.3 跟踪丢失（Tracking Loss）决策树

```
跟踪丢失
├─ 1. 检查运动
│  ├─ 运动是否过快？
│  │  ├─ 是（>1m/s 或 >90deg/s） → 根因: 运动过快
│  │  └─ 否 → 继续
│  └─ 是否有剧烈旋转？
│     ├─ 是 → 根因: 旋转运动过大
│     └─ 否 → 继续
│
├─ 2. 检查特征
│  ├─ 特征数量是否充足？
│  │  ├─ 否（<50） → 根因: 特征数量不足
│  │  └─ 是 → 特征分布是否均匀？
│  │     ├─ 否（集中在边缘/平面） → 根因: 特征分布不均
│  │     └─ 是 → 继续
│  └─ 特征质量如何？
│     ├─ 差（响应值低） → 根因: 特征质量差
│     └─ 好 → 继续
│
├─ 3. 检查匹配
│  ├─ 内点比例是否合理？
│  │  ├─ 否（<30%） → 根因: 匹配质量差
│  │  └─ 是 → 继续
│  └─ 是否有大量误匹配？
│     ├─ 是 → 根因: 匹配策略问题
│     └─ 否 → 继续
│
├─ 4. 检查场景
│  ├─ 是否纹理不足？
│  │  ├─ 是 → 根因: 场景纹理不足
│  │  └─ 否 → 是否有大量动态物体？
│  │     ├─ 是 → 根因: 动态物体干扰
│  │     └─ 否 → 继续
│  └─ 是否有遮挡？
│     ├─ 是 → 根因: 遮挡问题
│     └─ 否 → 继续
│
└─ 5. 检查相机
   ├─ 曝光是否正常？
   │  ├─ 否（过曝/欠曝） → 根因: 曝光问题
   │  └─ 是 → 继续
   └─ 是否有运动模糊？
      ├─ 是 → 根因: 运动模糊
      └─ 否 → 根因: 未知（需要更多日志）
```

#### 2.5 回环检测失败（Loop Closure Failure）决策树

```
回环检测失败
├─ 1. 检查回环候选
│  ├─ 是否有回环候选？
│  │  ├─ 否 → 根因: 无回环候选（描述子/词袋问题）
│  │  └─ 是 → 候选数量是否合理？
│  │     ├─ 否（太少） → 根因: 候选筛选过严
│  │     └─ 是 → 继续
│  └─ 候选质量如何？
│     ├─ 差（得分低） → 根因: 描述子区分度差
│     └─ 好 → 继续
│
├─ 2. 检查几何验证
│  ├─ 几何验证是否通过？
│  │  ├─ 否 → 根因: 几何验证过严/外参错误
│  │  └─ 是 → 继续
│  └─ 验证容差是否合理？
│     ├─ 否（过严/过松） → 根因: 验证容差不当
│     └─ 是 → 继续
│
├─ 3. 检查关键帧
│  ├─ 关键帧间隔是否合理？
│  │  ├─ 否（太大） → 根因: 关键帧选取策略问题
│  │  └─ 是 → 继续
│  └─ 关键帧质量如何？
│     ├─ 差（模糊/遮挡） → 根因: 关键帧质量问题
│     └─ 好 → 继续
│
├─ 4. 检查感知混叠
│  ├─ 是否有相似但不同的地方？
│  │  ├─ 是 → 根因: 感知混叠
│  │  └─ 否 → 继续
│  └─ 描述子是否区分度足够？
│     ├─ 否 → 根因: 描述子区分度不足
│     └─ 是 → 继续
│
└─ 5. 检查回环融合
   ├─ 回环是否正确融合？
   │  ├─ 否 → 根因: 回环融合逻辑错误
   │  └─ 是 → 继续
   └─ 融合后地图是否一致？
      ├─ 否 → 根因: 地图一致性问题
      └─ 是 → 根因: 未知（需要更多日志）
```

### Step 3: 评估置信度

对每个可能的根因，评估置信度：

- **高置信度**：有直接证据（日志/参数/代码）支持
- **中置信度**：有间接证据支持，但无法完全确认
- **低置信度**：基于经验推测，需要进一步验证

### Step 4: 输出根因分析

```markdown
🔍 **根因分析**

### 最可能的根因（置信度: {高/中/低}）

**根因**: {根因描述}

**证据**:
1. {证据1}
2. {证据2}
3. {证据3}

**决策树路径**:
```
{故障类型}
└─ {第N层检查}
   └─ {具体分支}
      └─ 根因: {根因}
```

### 其他可能原因

| 排名 | 根因 | 置信度 | 证据 |
|------|------|--------|------|
| 2 | {根因2} | {中/低} | {证据} |
| 3 | {根因3} | {低} | {证据} |

### 信息缺口

- ❓ {缺失的信息1}
- ❓ {缺失的信息2}

建议: {如何获取缺失信息}
```

## 注意事项

1. **优先级排序**：从最可能的原因开始排查（基于经验和统计）
2. **证据驱动**：每个判断必须有证据支持（日志/参数/代码）
3. **置信度标注**：明确标注每个根因的置信度
4. **信息缺口**：如果信息不足无法判断，明确指出需要哪些信息
5. **框架特化**：如果识别出项目使用的框架，加载框架特化的决策树
