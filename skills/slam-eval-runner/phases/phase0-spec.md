# Phase 0: 读取配置

## 目标

从 project-spec.md 中读取评估相关配置，确定评估脚本、轨迹文件、真值文件等信息。

## 触发词

- "读取评估配置"

## 依赖

project-spec.md（由 slam-project-profiler 生成）

## 输入参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| project_path | string | ✅ | 项目根目录绝对路径 |
| traj_file | string | ⬜ | 轨迹文件路径（可选，覆盖 spec 中的默认值） |
| gt_file | string | ⬜ | 真值文件路径（可选，覆盖 spec 中的默认值） |

## 输出产物

不生成文件，但产出配置信息供后续 Phase 使用。

## 执行步骤

### Step 1: 检查 spec 文件

检查 `{project}/.specs/project-spec.md` 是否存在。

如果不存在，输出错误并引导用户执行 profiler：

```
⚠️ 缺少项目规格文件

路径: {project}/.specs/project-spec.md

解决方案:
  先执行 slam-project-profiler 生成项目规格

是否需要我帮你执行 profiler？(Y/n)
```

### Step 2: 读取评估配置

从 spec 文件的 `## 6. 评估` 章节提取以下信息：

| 配置项 | spec 章节 | 必须 | 说明 |
|--------|----------|------|------|
| 评估脚本路径 | 6.1 评估脚本 | ✅ | 评估脚本的绝对路径 |
| 运行命令 | 6.1 评估脚本 | ✅ | 完整的运行命令模板 |
| 输出格式 | 6.2 评估输出格式 | ✅ | 评估脚本的输出格式说明 |
| 关注指标 | 6.3 关注指标 | ✅ | 项目关注的指标列表 |
| 指标含义 | 6.3 关注指标 | ✅ | 每个指标的含义和单位 |
| 合格阈值 | 6.3 关注指标 | ⬜ | 指标合格阈值（如有） |

### Step 3: 读取数据配置

从 spec 文件的 `## 3. 真值` 和 `## 4. 系统输出` 章节提取：

| 配置项 | spec 章节 | 必须 | 说明 |
|--------|----------|------|------|
| 真值文件路径 | 3. 真值 | ✅ | 真值文件的绝对路径 |
| 真值格式 | 3. 真值 | ✅ | TUM / EuRoC / KITTI / 自定义 |
| 轨迹文件路径 | 4.1 轨迹输出 | ✅ | 轨迹文件的绝对路径 |
| 轨迹格式 | 4.1 轨迹输出 | ✅ | TUM / EuRoC / KITTI / 自定义 |

### Step 4: 验证文件存在性

检查以下文件是否存在：
- 评估脚本
- 轨迹文件（如果用户未指定，使用 spec 中的默认路径）
- 真值文件

如果用户指定了轨迹文件路径，使用用户指定的路径。

### Step 5: 解析运行命令

将 spec 中的运行命令模板与实际文件路径结合：

**命令模板中的占位符**：
- `{traj}` 或 `{trajectory}` → 轨迹文件路径
- `{gt}` 或 `{groundtruth}` → 真值文件路径
- `{output}` → 输出文件路径（如果需要）

**示例**：
```
spec 中的命令模板: python scripts/evaluate.py --traj {traj} --gt {gt}
实际命令: python scripts/evaluate.py --traj /data/traj.csv --gt /data/gt.txt
```

### Step 6: 汇总配置

输出配置汇总供用户确认：

```markdown
📋 **评估配置**

### 评估脚本
- 路径: {script_path}
- 命令: {full_command}

### 数据文件
- 轨迹文件: {traj_path}
- 真值文件: {gt_path}

### 关注指标
| 指标 | 含义 | 单位 | 合格阈值 |
|------|------|------|---------|
| {metric1} | {meaning1} | {unit1} | {threshold1} |
| ... | ... | ... | ... |

是否继续执行评估？(Y/n)
```

## 注意事项

1. **路径验证**：确保所有文件路径都是绝对路径且文件存在
2. **命令验证**：确保评估脚本有执行权限
3. **格式一致性**：检查轨迹和真值格式是否被评估脚本支持
4. **用户确认**：在执行评估前向用户确认配置是否正确
